# Лабораторная работа N4: ленивые последовательности, потоки и прогнозирование

Проект реализует обобщенную ленивую последовательность `LazySequence<T>`, набор потоков чтения и записи, а также прикладную задачу варианта 3.3: прогнозирование технических параметров по потоку событий и оценку отклонений фактических значений от прогноза.


## Основные части проекта

### Ordinal

`Ordinal` описывает длины и индексы ленивых последовательностей:

- `Ordinal::Finite(n)` - конечное значение;
- `Ordinal::Omega()` - бесконечная длина;
- `Ordinal::FromParts(omegaCoefficient, finitePart)` - значение вида `omega * k + n`;
- `ContainsIndex` - проверка, входит ли индекс в длину;
- `ToString` - текстовое представление длины;
- сравнение и сложение ординалов.


### LazySequence

`LazySequence<T>` вычисляет элементы только при обращении к ним. Уже вычисленные конечные элементы сохраняются во внутреннем кэше, поэтому повторный доступ к материализованной части не запускает генерацию заново.

Последовательность можно создать:

- пустой;
- из массива;
- из обычной `Sequence<T>`;
- из функции индекса `std::function<T(std::size_t)>`;
- из рекуррентного правила `std::function<T(Sequence<T>*)>`;
- конечной длины или бесконечной длины `Ordinal::Omega()`.

Внутри `LazySequence` есть уникальное состояние:

- каждая `LazySequence` владеет своим `State` через `std::unique_ptr<State>`;
- каждый `State` владеет своим генератором через `std::unique_ptr<Generator>`;
- при копировании `LazySequence` создается новое состояние, копируется кэш и клонируется генератор через виртуальный `Clone`;
- составные генераторы могут хранить исходные последовательности через `std::shared_ptr`, чтобы безопасно строить цепочки операций.

Основные операции:

- `Get(Ordinal)`, `GetFirst`, `GetLast`;
- `GetSubsequence`;
- `Append`, `Prepend`, `InsertAt`;
- `Concat`;
- `Map`, `Where`;
- `Reduce`, `ReduceFirstN`;
- `Take`;
- `GetEnumerator`;
- `GetMaterializedCount`.

Операции, которые создают новую ленивую последовательность, возвращают `std::unique_ptr<LazySequence<T>>`.

### Потоки

В `Streams.h` реализованы интерфейсы:

- `ReadOnlyStream<T>`;
- `WriteOnlyStream<T>`.

Реализации потоков:

- `SequenceReadStream<T>` - чтение из обычной `Sequence<T>`;
- `LazySequenceReadStream<T>` - чтение из `LazySequence<T>`;
- `StringReadStream<T>` - чтение токенов из строки с пользовательской десериализацией;
- `FileReadStream<T>` - построчное чтение из файла;
- `SequenceWriteStream<T>` - запись в последовательность;
- `FileWriteStream<T>` - запись строк в файл с пользовательской сериализацией.

Потоки чтения поддерживают:

- `Open`;
- `Close`;
- `Read`;
- `Seek`;
- `GetPosition`;
- `IsEndOfStream`;
- `IsCanSeek`;
- `IsCanGoBack`.

Для объектов, переданных по ссылке, потоки создают non-owning `std::shared_ptr`: поток использует объект, но не удаляет его. Для объектов, переданных через `std::shared_ptr`, конструкторы проверяют `nullptr`.

## Вариант 3.3: прогнозирование и коррекция

Реализована система прогнозирования значений технических параметров по потоку событий. Система получает события, например загрузку CPU, загрузку памяти, температуру или количество ошибок запросов, строит прогноз следующего значения, сравнивает прогноз с фактическим значением и определяет степень отклонения: нормальное состояние, предупреждение или критическая ситуация.

Прикладной слой находится в `classes/headers/ForecastCorrection.h`.

### Событие

Входной поток состоит из объектов `Event`. Каждое событие содержит:

- `id` - номер события;
- `timestamp` - время события;
- `type` - тип технического параметра;
- `value` - фактическое числовое значение;
- `source` - имя источника.

Поддерживаемые типы событий:

- `CPU_LOAD` - загрузка CPU;
- `MEMORY_LOAD` - загрузка памяти;
- `TEMPERATURE` - температура;
- `REQUEST_ERRORS` - количество ошибок запросов.

### Модель прогноза

Для прогнозирования используется `DifferenceForecastModel`. Она строит прогноз по истории предыдущих значений того же типа события.

Поддерживаются два порядка модели:

- порядок `1` - прогноз по последней разности между двумя соседними значениями;
- порядок `2` - прогноз с учетом изменения разности, то есть простая конечно-разностная модель второго порядка.

Если истории пока недостаточно, прогноз не строится, а результат помечается как `NO_PREDICTION`.

История хранится в `HistoryBuffer`. Для каждого типа события используется отдельный буфер, поэтому поток может смешивать разные параметры: например, события CPU и температуры не влияют на прогноз друг друга.

### Коррекция и реакция

`CorrectionService` сравнивает предыдущий прогноз с фактическим значением текущего события:

- считает ошибку `actual - predicted`;
- считает абсолютную ошибку;
- сравнивает абсолютную ошибку с порогами предупреждения и критического отклонения.

`DecisionMaker` преобразует результат сравнения в реакцию:

- `NO_PREDICTION` - данных еще недостаточно;
- `NORMAL` - значение находится в пределах прогноза;
- `WARNING` - заметное отклонение;
- `CRITICAL` - критическое отклонение.

Главный класс обработки - `ForecastCorrectionProcessor`. Для каждого входного события он:

1. Берет прогноз, рассчитанный ранее для этого типа события.
2. Сравнивает прогноз с фактическим значением.
3. Вычисляет ошибку и абсолютную ошибку.
4. Определяет реакцию по порогам.
5. Добавляет событие в историю соответствующего типа.
6. Строит прогноз на следующий шаг.
7. Возвращает `ProcessingResult` с событием, предыдущим прогнозом, коррекцией, реакцией и новым прогнозом.

### Потоковая обработка

События могут поступать из `LazySequence<Event>` через `LazySequenceReadStream<Event>`. Результаты обработки записываются в `SequenceWriteStream<ProcessingResult>`, а при необходимости сохраняются в файл через `FileWriteStream<ProcessingResult>`.

Для демонстрации и тестов есть `EventGenerator`:

- `Linear` - линейный поток значений;
- `WithSpike` - поток с резким скачком;
- `Noise` - поток с небольшим шумом.

Также реализованы:

- `SerializeEvent`;
- `DeserializeEvent`;
- `SerializeProcessingResult`.

Формат CSV для входного события:

```text
id,timestamp,type,value,source
1,1000,CPU_LOAD,40,server-1
2,2000,CPU_LOAD,45,server-1
```

## Консольный интерфейс

`classes/cpp/UI.cpp` содержит русскоязычный интерактивный интерфейс.

Главное меню позволяет:

1. Работать с конечной `LazySequence`.
2. Создавать `LazySequence` через генератор.
3. Читать обычную последовательность через поток.
4. Читать `LazySequence` через поток.
5. Читать данные из строки.
6. Записывать данные в последовательность.
7. Работать с файловыми потоками.
8. Запускать встроенные автоматические проверки.
9. Выполнять нагрузочную проверку `LazySequence`.
10. Выполнять нагрузочную проверку файловых потоков.
11. Запускать демонстрацию варианта 3.3.

Для `LazySequence` доступны генераторы:

- числа Фибоначчи;
- арифметическая прогрессия;
- геометрическая прогрессия;
- квадраты натуральных чисел;
- кубы натуральных чисел;
- факториалы;
- линейная формула `a*n + b`;
- натуральные числа.

В разделе варианта 3.3 можно:

- настроить порядок модели, размер истории и пороги ошибок;
- вручную ввести события;
- сгенерировать линейный поток;
- сгенерировать поток со скачком;
- сгенерировать поток с шумом;
- загрузить события из CSV-файла;
- выполнить большой автоматический прогон и посмотреть статистику.

Для каждого обработанного события UI показывает фактическое значение, предыдущий прогноз, ошибку, реакцию и прогноз на следующий шаг.

## Сборка и тестирование

Проект собирается через CMake. Основные цели:

- `fourthlab` - консольная программа;
- `lab4_tests` - тесты GoogleTest.

Команды из build-директории:

```bash
cmake --build . --target fourthlab
cmake --build . --target lab4_tests
```

Тесты покрывают:

- операции `Ordinal`;
- ленивую материализацию и кэширование;
- конечные и бесконечные `LazySequence`;
- операции `Append`, `Prepend`, `InsertAt`, `Concat`, `GetSubsequence`;
- `Map`, `Where`, `Reduce`, `ReduceFirstN`, `Take`;
- потоки чтения и записи;
- ошибки состояния потоков и файловые ошибки;
- историю событий и разностную модель прогноза;
- классификацию отклонений `NORMAL`, `WARNING`, `CRITICAL`, `NO_PREDICTION`;
- обработку смешанных типов событий;
- CSV-сериализацию событий;
- большой ленивый поток событий для варианта 3.3.
